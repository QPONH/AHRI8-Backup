 收藏夹备份工具

把一个漫画镜像站上**你自己收藏夹里的作品**批量备份成本地图片。程序直连站点。
自带标题解密，目录名用真实的作品名与作者名。

本版要点：

- 发布物仍然只有**一个 `AHRI8Backup.exe`**，目标机器不需要安装 .NET 运行时，也不写 `%TEMP%`；
- 支持 **JPEG / PNG / GIF / WebP**，动图按实际内容保存为 `.gif`；
- 下载中可**暂停 / 继续**；
- 遇到会话失效（401/403、页面变成登录页）会**自动暂停并重新验证会话**，成功后继续；
- 每张图片的下载日志 + 断点续传 + 不依赖日志的损坏文件夹检查；
- **「检查所有文件」**：一次扫描输出目录下所有作品文件夹，列出缺页/坏图并记住结果，可单独补下载；
- 图片地址 404 时自动尝试**备用地址**（换宽度档 / 原图 / 去掉章节目录），解决个别作品永远下载失败。

> 只用于备份自己有权访问的收藏内容，请遵守站点条款并保持低并发。

## 一、运行（没有“运行时依赖”）

直接双击 `AHRI8Backup.exe` 即可，发布包里只有一个 exe：

| 项目 | 说明 |
|---|---|
| 运行时 | **不需要安装。** 程序目标为 .NET Framework 4.8，Windows 10 1903+ 与 Windows 11 已自带。 |
| 额外 DLL | **没有。** HTML 解析组件已嵌入 exe，启动时从内存加载；JSON 使用系统自带的 `System.Web.Extensions`。 |
| 临时目录 | **不写 `%TEMP%`。** 不会出现旧版自包含包“首次启动要自解压、临时目录不可写就无窗口”的问题。 |
| 网络 | 需要能访问站点域名。 |
| 图标 | exe 与窗口图标来自同一张多尺寸 `.ico`（源码 `Assets/app.ico`，由 `Assets/app.png` 生成）。 |

如果目标系统是 **Windows 8.1 / 更早版本 / 没装 .NET Framework 4.8 的 Win10 1809 之前版本**，
系统会提示安装 .NET Framework 4.8（微软官方免费）。Windows 10 1903+ / Windows 11 无需处理。

**建议双击运行，不要从其它工具/沙箱内启动。** 从受限环境启动时，程序对工作目录之外的位置只有读权限，
会出现“无法创建目录 / 无法保存设置”，程序会给出提示但下载无法完成。

## 二、使用步骤

1. **填站点地址**
   - `站点根地址`：默认已填当前镜像域名，例如 `https://ahri8-2026-08-10-c.top/`。**镜像换域名时只改这一项。**
   - `收藏夹地址`：默认已填 `…/index.php?route=account/favorite`。
2. **填账号密码**（站点需要登录时）
   - 密码只用于本次登录，不会写进日志。
   - 勾选 `记住文本` 才会把站点地址、收藏夹地址、输出目录、账号存到本机设置文件；
     勾选 `记住密码` 才会保存密码，且用**当前 Windows 用户的 DPAPI 加密**，只有本机本用户能解。
3. **点「登录 / 验证会话」**，日志显示“登录请求看起来成功”即可。
4. **点「扫描收藏夹」**，只请求网页 HTML，不下载图片。结果会列在下方表格里（标题 / ID / 状态 / 地址）。
   - 数量不对或标题异常时，先点「扫描并加入第一页作品」，它会打印页面标题、疑似链接样本等诊断信息。
5. **核对列表**，先选中一部作品点「测试下载选中作品」，确认能正常下载。
6. **开始下载**：`并发下载全部` 下载全部作品；也可以只下当前页或某个序号范围（见第四节）。默认同时处理 3 部作品、全局最多 8 张图片请求。
   - 中途可点 **「暂停」** 暂停（不再发出新请求，已完成的图片不会丢），点 **「继续」** 从当前进度接着跑。
   - 点「停止」会结束整批任务；已完成的图片同样会保留，下次扫描后继续即可。
7. 结果保存在输出目录下，每部作品一个文件夹，内含：
   - `0001.jpg` / `0002.gif` / `0003.png`…：图片（下载中先写 `.part`，校验通过后才改成正式文件名）；
   - `download.log.jsonl`：**下载日志**，每成功/失败一张立即追加一行（见第六节）；
   - `manifest.json`：整部作品的汇总信息（最后写入）。

### 两个并发数是什么意思

| 设置 | 含义 | 默认 | 范围 |
|---|---|---|---|
| `并发作品数` | **同时处理几部作品**。每部作品是一个独立任务：解析详情页 → 逐页解析阅读页 → 下载图片。 | 3 | 1–6 |
| `图片并发数` | **所有作品合计**同时发出的图片请求上限，是全局闸门。 | 8 | 1–16 |

调高都更快，但更容易被站点限速或 CDN 拦截。不确定就保持默认；如果经常出现图片失败，先调低 `图片并发数`。

### 界面

- 按钮行：`登录 / 验证会话`、`扫描收藏夹`、`扫描并加入第一页作品`、`测试下载选中作品`、`并发下载全部`、
  `停止`、`暂停 / 继续`、`修复启动被拦`，最后是当前状态文字。
- 第二行按钮：`下载本页`、`下载选中`、序号范围 + `下载该范围`、`检查文件夹完整性`、**`检查所有文件`（新增）**。
- **`深色界面` 复选框已移到设置区的“选择目录…”右侧**，勾选为深色、取消为浅色，选择会被记住。
- `修复启动被拦`：一键处理“每次启动都被 Windows 要求手动同意”，见常见问题。

每个输入框下方都有一行灰色说明，写明该字段的含义与默认值。启动日志会打印当前两个并发值和设置文件路径。

### 三级进度条

| 进度条 | 显示什么 |
|---|---|
| `单文件` | 当前正在传输的那张图：已收字节 / 总字节，以及 MB 数（续传时会把已下载部分算进去） |
| `单文件夹` | **所有正在下载的作品合计**的图片张数（如 `6/20 张 · 3 部在下载`） |
| `总进度` | 整批作品完成数（如 `12/24 部`） |

任务结束或空闲时三个条归零并显示 `—`。进度由 150ms 的计时器刷新。

## 三、目录命名规则

界面上的 `命名方式` 下拉框决定用哪一种，**选择会被记住**。

### ① 页-序号（默认）

```
标题{作者}{收藏夹页码,页内序号}
```

例：作品 `a`、作者 `b`，位于收藏夹第 1 页第 3 个 → `a{b}{1,3}`

- 标题与作者来自页面里被 AES 加密的文本，程序按页面内嵌密钥解密后取得，格式是 `[作者]标题`。
- 方括号内用圆括号分隔的多个名字各算一位作者，会写成多个 `{作者}` 段。
  例如 `[甘霖组(金世兰)]某作品` → `某作品{甘霖组}{金世兰}{1,3}`。

### ② 倒序编号

```
标题{作者}{倒序号}
```

按扫描顺序（收藏夹页序 → 页内序）倒过来编号：**最后一本为 1，第一本为总数量**，
数字按总数位数补零以便排序。以 100 部为例：

| 列表序号 | 1 | 2 | 3 | … | 99 | 100 |
|---|---|---|---|---|---|---|
| 目录后缀 | `{100}` | `{099}` | `{098}` | … | `{002}` | `{001}` |

注意：序号依据**本次扫描到的列表**，所以先 `扫描收藏夹` 扫完整再切换命名方式；
只扫第一页时总数就只有那 20 部。

## 四、列表翻页与按范围下载

列表每页显示 **20 条**，与站点收藏夹每页数量一致。第一列是**全局序号**（收藏夹页序 → 页内序）。

| 按钮 | 作用 |
|---|---|
| `下载本页` | 只下载当前显示的这一页（20 部） |
| `下载选中` | 下载列表里选中的作品；按住 Ctrl 点选多个，或按住 Shift 选一段 |
| `下载该范围` | 按序号范围下载，例如 11 → 20。范围框默认就是当前页，直接点按钮即可 |
| `并发下载全部` | 下载列表里的全部作品 |
| `检查文件夹完整性` | 检查选中作品（未选则当前页）的本地文件夹，不联网、不改动文件；结果显示在日志里 |

**接着上次的进度继续**：状态列会显示 `已下载`、`已存在 N/M 张` 或 `待处理`。
“已经下完 1–10，下次直接下 11–20”的做法：扫描完成后把范围填成 `11` → `20`，点 `下载该范围`；
或翻到对应页点 `下载本页`。已存在的图片不会重复下载。

## 五、已有文件夹的检查（补全 / 忽略）

每次开始下载一部作品前，程序会先检查目标文件夹，**确认已有图片的完整度**：

- 判定“可用”的条件：文件存在、大于 100 字节、开头魔数正确、结尾标记完整。
  支持 **JPEG（`FF D8` … `FF D9`）、PNG（`IEND`）、GIF（`GIF87a/89a` … `0x3B`）、WebP（RIFF 长度核对）**。
  **0 字节、截断的图片、上次失败留下的错误页（HTML）都会被判为损坏**，不会被当成已完成。
- 查找已有图片时按 `0001.jpg` / `0001.jpeg` / `0001.png` / `0001.gif` / `0001.webp` 的顺序查找。
- 全部可用 → 直接标记 `已完成`，不发起任何图片请求。
- 部分缺失/损坏 → 按 `已存在文件夹` 下拉框的设置处理：
  - `补全缺失的图片`（默认）：只下缺的那几张，已有的一张都不重下，状态显示 `补全 N 张`。
  - `忽略整个作品`：该作品本次完全不下载，状态显示 `已存在，忽略`。
  - `逐个询问我`：弹窗可选 `补全` 或 `忽略`，也可选让本次任务剩下的作品都按“补全”处理不再询问。
- 检查结果写进日志，例如：
  `作品 73613 文件夹检查（直接读文件，不依赖日志）：14/20 张可用，损坏 1 张（0007），缺失 5 张（…）。`
- 列表的 `状态` 列显示 `已存在 14/20 张` 或 `已完整 20 张`（应有张数取自 `manifest.json`，没有 manifest 时用下载日志兜底）。

**这条检查不依赖日志**：即使 `download.log.jsonl` 写着某页 `ok`，只要文件实际损坏/缺失，仍会重新下载。
损坏的正式图片会在下载开始前被删除，避免被误当作已有文件。

## 六、下载日志与断点续传

### 日志文件

1. **每部作品的下载日志**：`输出目录\<作品文件夹>\download.log.jsonl`
   - 一行一条 JSON，**每张图片成功或失败后立即追加并落盘**（`Flush(true)`）。
   - 字段示例：
     ```json
     {"Time":"2026-10-19 19:40:01","Page":1,"Url":"https://…/0001_w1100.gif","File":"0001.gif","Status":"ok","Bytes":245678}
     ```
     失败时 `Status` 为 `failed` 并带 `Error`。
   - 同一页会保留最后一条记录：先失败、后成功时以成功为准；断电留下的半行会被跳过。
2. **整次运行的日志**：`输出目录\AHRI8Backup.log`
   - 记录启动、目录检查、每部作品进度、暂停/继续、会话重新验证、错误等人类可读信息。

### 断点续传怎么工作

每次开始下载一部作品时：

1. 先扫描该作品的 `download.log.jsonl`，得到上次“哪些页成功过”的线索；
2. **再直接检查磁盘上的文件**（不信任日志），把损坏/缺失的页挑出来；
3. 只请求需要补的页：
   - 如果上次中断留下了 `0007.jpg.part` / `0007.gif.part`，会带 `Range: bytes=<已有字节>-` 从断点继续；
   - 服务器不支持续传（回 `200` 而不是 `206`）时，自动从头下载；
   - 下载完成后校验图片头尾，通过才改名为正式文件（扩展名按实际内容）并写日志。
4. 因此：**中途暂停、停止、断网、关掉程序甚至重启电脑都不会丢掉已完成的页**；下次对同一批作品执行下载即可继续。

> 日志只是线索，不代替实际文件检查。删除日志不会让已完成的图片重新下载（文件检查会通过），
> 但删除图片文件后即使日志写着 `ok` 也会重新下载。

## 七、暂停 / 继续 与会话失效自动恢复（新增）

### 暂停 / 继续

- 下载过程中点 **「暂停」**，按钮变成 **「继续」**：
  - 不再发出新的 HTTP 请求（作品开始、详情页、每个阅读分页、每张图片之前都会检查暂停闸门）；
  - 已经发出的请求会自然完成；
  - 已经下载成功的图片、日志、manifest 都会保留。
- 点 **「继续」** 从暂停处接着跑，不需要重新扫描。
- 暂停期间点 **「停止」** 仍然可以结束任务。

### 会话失效自动暂停 + 重新验证

- 当请求出现 **HTTP 401 / 403**，或详情页/阅读页**被重定向成登录页**时，视为登录会话失效：
  1. 立即暂停整批任务（状态显示 `已暂停（会话失效）`）；
  2. 自动用界面上的账号密码**重新验证会话**（与「登录 / 验证会话」相同的流程）；
  3. 验证成功 → 自动继续任务，并把刚才失败的那部作品重试一次；
  4. 验证失败（例如需要验证码）→ 保持暂停，日志给出原因；修正账号/验证码后点「继续」会再次尝试验证。
- 多个作品同时遇到失效时只会重新登录一次，不会反复提交账号密码。
- 暂停日志示例：
  `任务已暂停（会话失效，等待重新验证）。…`
  `正在重新验证会话（重新登录）…`
  `会话已重新验证，任务继续。`

## 八、图片格式支持（新增）

| 格式 | 保存扩展名 | 完整性判断 |
|---|---|---|
| JPEG | `.jpg` | 开头 `FF D8`，末尾 4KB 内找到 `FF D9` |
| PNG | `.png` | PNG 签名，末尾 4KB 内找到 `IEND` |
| GIF（含动图） | `.gif` | `GIF87a` / `GIF89a`，末尾附近有 `0x3B` 结束标记 |
| WebP | `.webp` | `RIFF....WEBP`，并按头部声明长度核对是否截断 |

- 站点脚本里的 `extension` 字段会参与图片地址构造（`_w1100.gif` 等），GIF 地址原样请求。
- **最终文件名以实际内容为准**：如果 URL 写 `.jpg` 但响应内容是 GIF，会保存为 `0001.gif` 并在日志里说明。
- 断点续传的 `.part` 同样按扩展名区分；旧的 JPEG 文件夹继续可用，不会被重复下载。

## 九、检查所有文件与单独下载（新增）

「检查所有文件」会扫描**输出目录下的所有作品文件夹**（不只是当前页/选中项），逐个验证每张图片：

- 判定标准与第五节相同（JPEG / PNG / GIF / WebP 的魔数 + 结尾标记）；`.part` 未完成文件也会列出。
- 结果窗口列出：作品、文件夹、可用/应有张数、损坏页、缺失页、检查时间、是否可单独下载。
- 结果保存到 `输出目录\incomplete.json`，**下次打开窗口会自动读回**（“记住”）；点「重新检查」会重新扫描并更新。
- 选中一行或多行 → **「下载选中」**：只补下载这些作品的缺失/损坏页；
  - 下载写回**原文件夹**（不重新计算目录名），所以即使当时用的是“倒序编号”也不会新建错误目录；
  - 下载前仍会执行一次文件完整性检查，已有可用图片不会重下；
  - 下载完成后窗口自动重新扫描，修好的作品从列表消失。
- 如果作品文件夹里没有 `manifest.json`（或其中没有 `WorkUrl`），无法单独下载，会显示“否（无地址）”；
  请在主界面重新扫描收藏夹后再下载整个作品。
- 双击一行或点「打开文件夹」可在资源管理器中定位该作品。

> 单独下载使用主窗口的账号、并发、暂停/继续与会话失效恢复逻辑；下载期间主窗口显示进度。
> 同一时间只能有一个任务在跑：如果主界面正在下载，请先等它完成或点「停止」。

### 图片地址 404 的自动回退（解决个别作品永远失败）

有些作品的图片地址按脚本拼出来后返回 **404**（例如该作品没有 `_w1100` 这个宽度档，
或者路径里多了一层 `/01/` 章节目录）。现在遇到 404 会自动尝试备用地址：

1. 换宽度档：`_w1600`、`_w1400`、`_w1200`、`_w1000`、`_w800`、`_w600`、`_w400`；
2. 去掉宽度后缀，直接取原图；
3. 去掉路径中的 `/01/` 这类两位数字章节目录，再重复 1、2。

成功的规则会被**记住**，同一个作品后面的页优先使用该规则，避免每页都先撞一次 404。
日志会写明“主地址不可用，已改用备用地址成功（规则）”；`manifest.json` 记录实际可用的 URL。
如果所有候选都 404，仍会按失败处理，不会留下错误文件。

## 十、常见问题

| 现象 | 原因与处理 |
|---|---|
| `无法创建目录：… is denied` | 输出目录不可写。程序会同时给出三条处理建议：改为直接双击运行、换一个可写目录、或检查安全软件/只读属性。 |
| 双击后**没有任何窗口** | 本版没有自解压步骤，正常情况下不会再出现。若仍出现，先确认系统是 Windows 10 1903+ / 11 且 .NET Framework 4.8 已启用，再把 `%TEMP%\AHRI8Backup-startup.log` / `%TEMP%\AHRI8Backup-crash.log`（如果有）发给作者。 |
| **每次启动都被 Windows 阻止，要手动点同意** | 点 `修复启动被拦`：清除“来自 Internet”标记，并可关闭 SmartScreen 的「检查应用和文件」。程序未做数字签名，这不是病毒查杀。 |
| 日志显示“页面像是登录页” / 任务自动暂停 | 会话失效。程序会自动重新登录；若失败，检查账号密码或验证码后点「继续」。 |
| 扫描到 0 部作品 | 登录 Cookie 没生效，或收藏夹地址不对。看日志里的“收藏页诊断”一行。 |
| 阅读页解析不到图片 | 日志会输出最终 URL、页面标题、img 数量与属性样本，便于继续适配。 |
| 图片反复失败 | 先调低 `图片并发数`；日志里会保留每页的失败原因。再次执行下载会只补失败页。 |
| GIF 下载后不动 | 确认文件夹里是 `.gif` 文件（程序按实际内容命名）；用看图软件/浏览器打开。损坏的 GIF 会被判坏并重下。 |
| 某个作品的所有图片都 404 | 程序会自动尝试备用宽度/原图/去章节目录；若仍失败，把日志里那一行“主地址不可用”发来，可继续补规则。 |
| `内置组件自检：HTML 解析器加载失败` | exe 被破坏或被杀软隔离了内嵌资源。重新下载/解压 exe，或把这一行发给作者。 |
| 中文目录名乱码 | 仅出现在第三方解压/同步工具上，Windows 资源管理器正常。 |

## 十一、从源码编译（离线可行）

需要 Windows + .NET SDK（4.8 目标，建议 .NET SDK 8/9/10）。**不需要联网还原 NuGet**：
HtmlAgilityPack 的 `net45` 版本已放在 `libs\HtmlAgilityPack.dll`，其余引用都来自 .NET Framework 自带组件。

```bat
:: 构建（产物：bin\Release\net48\AHRI8Backup.exe，单文件）
dotnet build AHRI8Backup.csproj -c Release
```

- 单文件怎么实现：`libs\HtmlAgilityPack.dll` 通过 `<EmbeddedResource>` 嵌进 exe，
  运行时由 `EmbeddedAssemblies.AssemblyResolve` 从内存加载；`Reference` 设置 `Private=false`，
  所以输出目录不会出现额外的 DLL。
- 图标：`Assets\app.ico` 作为 `ApplicationIcon` 嵌入 exe；窗口图标在运行时从同一份资源读取。
  重新生成图标（需要 Python + Pillow）：
  ```bat
  python tools\make-icon.py
  ```
- 版本号：`AHRI8Backup.csproj` 的 `<Version>`。

### 源码结构

| 文件 | 作用 |
|---|---|
| `MainForm.cs` | 界面、登录/扫描、下载调度、暂停/恢复、会话失效处理 |
| `ImageIntegrity.cs` | JPEG/PNG/GIF/WebP 识别与完整性校验、扩展名推断 |
| `FolderIntegrity.cs` | 不依赖日志的文件夹检查 |
| `IncompleteScanner.cs` | 「检查所有文件」的扫描与 `incomplete.json` 持久化 |
| `IncompleteWindow.cs` | 不完整作品列表窗口（单独下载） |
| `ImageUrlFallback.cs` | 图片 404 时的备用地址规则（宽度档 / 原图 / 去章节） |
| `DownloadLog.cs` | `download.log.jsonl` 的读写 |
| `JsonText.cs` | JSON 缩进（让 manifest/settings 可读） |
| `Compat.cs` | net48 缺失的 `IsExternalInit` 与 `string.Contains(StringComparison)` |
| `Program.cs` | 启动、嵌入程序集解析、未处理异常提示 |

## 十二、设置文件

位置：`%LocalAppData%\AHRI8Backup\settings.json`（只在本机、只对当前 Windows 用户）。
**首次运行时程序会自动创建该文件**；启动日志会打印完整路径。

- 密码用 DPAPI 加密后存放，换用户或换机器都无法解密。
- 删除该文件即可清空所有已记住的内容。
- **源码与程序本身不含任何账号、密码或个人信息**；账号密码输入框默认为空。

## 十三、已知限制

- 站点改版会导致选择器失效。程序会明确报错并打印诊断信息，不会静默产生错误目录名。
- 登录带验证码/短信验证、需要 JS 签名或设备指纹的站点不支持；这种情况下会话恢复会失败并保持暂停。
- 图片宽度后缀默认按 `_w1100` 构造；遇到 404 会自动尝试其他宽度/原图，但若站点完全改变路径规则，仍可能需要继续补适配。
- 不跳过 TLS 证书校验，不执行页面 JavaScript。
- 断点续传按**页号**匹配：如果两次扫描之间收藏夹内容变化导致阅读页的页序不同，日志里的页号可能与新页序错位；
  实际文件检查仍会保证不会把已下载的图片重复下载，但可能多取几张。
- 暂停只阻止新请求；正在传输的那张图会完成后才停在安全点。
